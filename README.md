# Agentic Clean Code

> Clean Code 이후, 코드는 누구를 위해 깨끗해야 하는가?

이 저장소는 **Agentic Clean Code**를 조사하고 집필하기 위한 연구 저장소다.

출발 가설은 단순히 "AI가 코드를 작성하므로 기존 Clean Code가 필요 없다"가 아니다. 기존의 가독성, 응집도, 결합도, 테스트 가능성 같은 원리는 여전히 유효하지만, Coding Agent가 소프트웨어 개발의 주요 실행 주체가 되면서 코드 품질의 평가 단위와 최적화 대상이 달라지고 있다는 문제의식에서 시작한다.

초기 연구에서는 다음 질문을 검증한다.

- Agent가 전체 저장소를 적게 읽고도 올바른 수정 위치를 찾을 수 있는가?
- 여러 Agent가 동시에 수정할 때 change blast radius와 merge conflict를 줄일 수 있는가?
- Agent가 사람의 수동 조작 없이 실패를 재현하고 수정 결과를 검증할 수 있는가?
- 로그, 테스트, 타입, 아키텍처 규칙이 Agent에게 다음 행동을 직접 알려줄 수 있는가?
- 저장소 지식과 실행 환경을 어떤 방식으로 구성해야 context 비용과 오류를 줄일 수 있는가?
- 기존 Clean Code의 원칙 중 무엇이 유지되고, 무엇이 재정의되어야 하는가?

현재 단계는 **리서치 우선**이다. 결론을 먼저 고정하지 않고 실험, 논문, 실제 agent-first 개발 사례, 반례를 함께 수집한다.
