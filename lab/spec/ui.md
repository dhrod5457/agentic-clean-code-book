# 화면 명세

관리자 화면 9개의 구성, 열, 버튼 이름, 표시 형식이다. 기준 화면 폭은 1280px 이다.
버튼 · 입력 이름은 이 문서의 문자열을 그대로 쓴다. 시험은 role 과 접근 가능한 이름으로 요소를 찾는다.

## 1. 공통 레이아웃

- 로그인 화면을 뺀 모든 화면은 머리말, 왼쪽 메뉴, 본문으로 구성한다
- 머리말: 왼쪽에 "쇼핑몰 관리자", 오른쪽에 현재 사용자 `이름 (역할 이름)` 과 "로그아웃" 버튼
- 왼쪽 메뉴 폭 220px, 본문 안쪽 여백 24px
- 글꼴: `font-family: "Noto Sans KR", sans-serif`, 기본 글자 크기 14px
- 본문 첫 줄에 화면 제목(`h1`)을 둔다. 화면 제목은 §5 의 각 화면 이름이다(예: 회원 목록, 회원 상세). 로그인 화면의 제목은 "쇼핑몰 관리자 로그인" 이다
- 확인 창은 브라우저 기본 창(`alert`, `confirm`)을 쓰지 않는다. 쓰기 동작은 버튼을 누르면 바로 실행한다
- 쓰기 동작이 성공하면 그 화면의 데이터(목록 또는 상세)를 다시 불러온다
- 쓰기 동작이 실패하면 응답의 `message` 를 본문 위 알림 영역(`role="alert"`)에 표시한다
- 성공 안내 문구는 본문 위 안내 영역(`role="status"`)에 표시한다
- 상세 화면과 배송 정책 화면의 표시 항목은 `dl` 안에 항목 이름(`dt`)과 값(`dd`) 쌍으로 둔다
- 목록에서 고르는 입력(역할 등)은 `select` 요소이고, option 의 표시 문자열은 §4 의 표시 이름이다
- 로그인하지 않은 상태로 다른 화면에 들어가면 `/login` 으로 이동한다. 로그인하면 `/members` 로 이동한다. `/` 는 `/members` 로 이동한다. 로그아웃하면 `/login` 으로 이동한다
- 화면에 필요한 `_READ` 권한이 없으면 본문에 "권한이 없습니다." 를 표시한다

## 2. 목록 표(`DataTable`)

모든 목록은 같은 표 component 를 쓴다.

- 표는 표 컨테이너 안에 둔다. 컨테이너는 `overflow-x: auto` 이고, 표의 `min-width` 는 100% 다
- 셀 텍스트는 줄바꿈하지 않는다(`white-space: nowrap`). 셀 내용이 길면 표가 넓어지고 컨테이너에 가로 스크롤이 생긴다
- 열 순서는 §5 의 표 순서다. 버튼 열은 항상 마지막 열이고 머리글은 "처리" 다. 그 화면의 쓰기 권한이 없으면 "처리" 열을 표시하지 않는다
- 표는 `table` 요소다. 머리글 행은 `thead` 안의 `th`, 데이터 행은 `tbody` 안의 `tr` 과 `td` 다
- 상태별 표시
  - 로딩 중: "불러오는 중입니다."
  - 빈 목록: "데이터가 없습니다."
  - 오류: "데이터를 불러오지 못했습니다." 와 "다시 시도" 버튼

## 3. 메뉴

메뉴는 `nav`(접근 가능한 이름 "주메뉴") 안에 그룹마다 그룹 이름 제목(`h2`)과 항목 목록(`ul`)을 둔다. 항목은 링크이고 현재 화면의 링크에 `aria-current="page"` 를 붙인다.

그룹 순서는 고정이다. 그룹 안 항목은 이름의 가나다순이다. 권한이 없는 항목은 표시하지 않고, 항목이 모두 숨겨진 그룹도 표시하지 않는다.

| 그룹 | 항목 | 경로 | 필요 권한 |
|---|---|---|---|
| 회원 | 회원 목록 | `/members` | `MEMBER_READ` |
| 주문 | 주문 목록 | `/orders` | `ORDER_READ` |
| 배송 | 배송 목록 | `/deliveries` | `DELIVERY_READ` |
| 배송 | 배송 정책 | `/delivery-policy` | `DELIVERY_READ` |
| 환불 | 환불 목록 | `/refunds` | `REFUND_READ` |
| 설정 | 관리자 계정 | `/staff` | `STAFF_READ` |

메뉴에 넣지 않는 화면: 로그인(`/login`), 회원 상세(`/members/:id`, `MEMBER_READ`), 주문 상세(`/orders/:id`, `ORDER_READ`).

## 4. 표시 형식

| 값 | 형식 | 예 |
|---|---|---|
| 금액 | 천 단위 쉼표와 "원" | `150,000원`, `0원` |
| 시각 | `YYYY-MM-DD HH:mm` (Asia/Seoul) | `2026-01-15 10:00` |
| 값 없음(`null`) | `-` | `-` |

| enum | 표시 이름 |
|---|---|
| 회원 등급 | `GENERAL` 일반, `VIP` VIP |
| 회원 상태 | `ACTIVE` 활성, `SUSPENDED` 정지, `WITHDRAWN` 탈퇴 |
| 주문 상태 | `PENDING_PAYMENT` 결제 대기, `PAID` 결제 완료, `EXPIRED` 만료 |
| 배송 상태 | `READY` 출고 대기, `SHIPPED` 배송 중, `DELIVERED` 배송 완료 |
| 환불 상태 | `REQUESTED` 요청, `APPROVED` 승인, `REJECTED` 거절 |
| 환불 구분(`partial`) | `true` 부분, `false` 전체 |
| 역할 | `ADMIN` 관리자, `OPERATOR` 운영자 |
| 계정 상태(`active`) | `true` 활성, `false` 비활성 |

## 5. 화면

### 5.1 로그인 (`/login`)

- 입력: "로그인 ID", "비밀번호"(type password)
- 버튼: "로그인"
- 실패하면 응답의 `message` 를 `role="alert"` 영역에 표시한다

### 5.2 회원 목록 (`/members`)

| 열 | 값 |
|---|---|
| ID | `id` |
| 이름 | `name`. 회원 상세로 가는 링크 |
| 이메일 | `email` |
| 등급 | `grade` 표시 이름 |
| 상태 | `status` 표시 이름 |
| 가입일시 | `joinedAt` |
| 마지막 로그인 | `lastLoginAt` |

버튼 열 없음.

### 5.3 회원 상세 (`/members/:id`)

표시 항목(항목 이름과 값의 목록): ID, 이름, 이메일, 등급, 상태, 가입일시, 마지막 로그인, 탈퇴일시.

버튼(`MEMBER_WRITE` 가 있고 회원이 탈퇴하지 않았을 때만):

| 버튼 | 표시 조건 | 동작 |
|---|---|---|
| 정지 | 상태 `ACTIVE` | 상태를 `SUSPENDED` 로 변경 |
| 정지 해제 | 상태 `SUSPENDED` | 상태를 `ACTIVE` 로 변경 |
| VIP로 변경 | 등급 `GENERAL` | 등급을 `VIP` 로 변경 |
| 일반으로 변경 | 등급 `VIP` | 등급을 `GENERAL` 로 변경 |
| 탈퇴 처리 | 항상 | 탈퇴 처리 |

이 화면은 회원 정보만 표시한다. 주문 · 환불 정보를 넣지 않는다.

### 5.4 주문 목록 (`/orders`)

| 열 | 값 |
|---|---|
| ID | `id`. 주문 상세로 가는 링크 |
| 회원 ID | `memberId` |
| 상태 | `status` 표시 이름 |
| 상품 금액 | `productAmount` |
| 배송비 | `deliveryFee` |
| 결제 금액 | `totalAmount` |
| 주문일시 | `createdAt` |
| 결제일시 | `paidAt` |

목록 위 버튼(`ORDER_WRITE`): "만료 처리". 누르면 `POST /api/admin/orders/expire-overdue` 를 호출하고 `N건을 만료 처리했습니다.` 를 안내 영역(`role="status"`)에 표시한 뒤 목록을 다시 불러온다.

### 5.5 주문 상세 (`/orders/:id`)

표시 항목: ID, 회원 ID, 상태, 상품 금액, 배송비, 결제 금액, 주문일시, 결제일시, 만료일시.

상품 표(`DataTable`):

| 열 | 값 |
|---|---|
| 상품명 | `productName` |
| 단가 | `unitPrice` |
| 수량 | `quantity` |
| 금액 | `lineAmount` |

### 5.6 배송 목록 (`/deliveries`)

| 열 | 값 |
|---|---|
| ID | `id` |
| 주문 ID | `orderId` |
| 상태 | `status` 표시 이름 |
| 배송비 | `fee` |
| 등록일시 | `createdAt` |
| 출고일시 | `shippedAt` |
| 도착일시 | `deliveredAt` |
| 처리 | 버튼(`DELIVERY_WRITE`) |

| 버튼 | 표시 조건 | 동작 |
|---|---|---|
| 출고 처리 | 상태 `READY` | 상태를 `SHIPPED` 로 변경 |
| 도착 처리 | 상태 `SHIPPED` | 상태를 `DELIVERED` 로 변경 |

### 5.7 배송 정책 (`/delivery-policy`)

표시 항목: "기본 배송비" `baseFee`, "VIP 무료배송 기준 금액" `vipFreeShippingThreshold`.
항목 아래에 안내 문장 "VIP 회원의 상품 금액이 기준 금액 이상이면 배송비가 0원입니다." 를 둔다. 수정 기능은 없다.

### 5.8 환불 목록 (`/refunds`)

| 열 | 값 |
|---|---|
| ID | `id` |
| 주문 ID | `orderId` |
| 구분 | `partial` 표시 이름 |
| 요청 금액 | `amount` |
| 배송비 차감 | `deliveryFeeDeduction` |
| 환불 금액 | `refundedAmount` |
| 상태 | `status` 표시 이름 |
| 요청일시 | `requestedAt` |
| 처리일시 | `processedAt` |
| 처리 | 버튼(`REFUND_WRITE`, 상태 `REQUESTED` 일 때): "승인", "거절" |

목록 위 버튼(`REFUND_WRITE`): "환불 요청 등록". 누르면 목록 위에 입력 영역을 연다.

- 입력: "주문 ID", "요청 금액", "사유"
- 버튼: "등록", "취소"
- 등록에 성공하면 입력 영역을 닫고 목록을 다시 불러온다

### 5.9 관리자 계정 목록 (`/staff`)

| 열 | 값 |
|---|---|
| 로그인 ID | `loginId` |
| 이름 | `name` |
| 부서 | `department` |
| 역할 | `role` 표시 이름 |
| 상태 | `active` 표시 이름 |
| 처리 | 버튼(`STAFF_WRITE`, 활성 계정일 때): "수정", "비활성화" |

- "수정": 그 행 아래에 역할 선택("역할")과 "저장", "취소" 버튼을 연다. 저장하면 역할을 변경한다
- "비활성화": 계정을 비활성화한다

목록 위 버튼(`STAFF_WRITE`): "관리자 계정 추가". 누르면 목록 위에 입력 영역을 연다.

- 입력: "로그인 ID", "이름", "부서", "역할"(선택), "비밀번호"(type password)
- 버튼: "등록", "취소"
- 등록에 성공하면 입력 영역을 닫고 목록을 다시 불러온다
